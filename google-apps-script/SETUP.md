# Заявки в Google Таблице и вход в админ-панель

GitHub Pages хранит страницы. Google Apps Script принимает заявки, проверяет пароль, управляет сессиями и публикует изменения в GitHub. Пароль и GitHub-токен не находятся в файлах сайта.

## Настройка один раз (в браузере)

1. Под своим Google-аккаунтом откройте https://script.google.com/home/start и создайте **Новый проект**.
2. Откройте [Code.gs](./Code.gs) в этом репозитории, нажмите **Raw**, скопируйте весь код и вставьте в `Код.gs` в редакторе Google вместо примера. Сохраните проект.
3. В Google Apps Script откройте **Настройки проекта → Свойства скрипта → Добавить свойство**:

   | Имя | Значение |
   | --- | --- |
   | `GITHUB_REPOSITORY` | `azgleb/azamat` (или актуальное имя, если переименовали репозиторий) |
   | `GITHUB_BRANCH` | `main` |
   | `GITHUB_TOKEN` | Ваш fine-grained GitHub token: только этот репозиторий, **Contents: Read and write** |
   | `ADMIN_USERNAME` | Ваш логин, например `azamat` |

   Токен создаётся на https://github.com/settings/personal-access-tokens/new. Его вводите только в **Свойства скрипта**. Не вставляйте его в код, GitHub-файлы, форму заявки или чат.

4. Вернитесь в редактор. Выберите функцию **setup** и нажмите **Выполнить**. Разрешите скрипту доступ к вашим таблицам и внешним запросам (GitHub). Google может показать предупреждение для вашего собственного непроверенного приложения — проверьте, что запускаете именно свой проект с этим кодом.
5. В **Журнале выполнения** появятся логин, сгенерированный пароль и ссылка на созданную таблицу. Сохраните пароль в менеджер паролей. Таблица приватная; не включайте «Доступ всем по ссылке».
6. Выберите **Развернуть → Новое развертывание → Веб-приложение**:
   - Выполнять от имени: **Я**.
   - У кого есть доступ: **Все** (включая посетителей без Google-аккаунта).
   - Нажмите **Развернуть**. Скопируйте URL вида `https://script.google.com/macros/s/…/exec`.
7. Этот URL не является паролем: его можно отправить в чат, чтобы мы подключили сайт. Либо самостоятельно измените единственное значение в [backend-config.js](../backend-config.js), вставив URL между кавычками, и сохраните коммит в `main`.
8. После обновления GitHub Pages откройте сайт и отправьте тестовую заявку. Убедитесь, что она появилась в таблице. Откройте `admin.html`, войдите с логином и паролем из журнала, проверьте «Заявки» и публикацию.

Если политика вашего Google Workspace запрещает веб-приложения с доступом «Все», нужен аккаунт/сервер, где такой доступ разрешён. Публичная ссылка на одну только Google Таблицу не заменяет развёртывание скрипта.

## Восстановление доступа

Для нового пароля выполните **resetAdminPassword** в своём редакторе Google Apps Script. Новый пароль появится только в вашем журнале выполнения; старый пароль и ранее выданные сессии перестанут действовать. Не пытайтесь запускать `setup` повторно.

Пароль генерируется длинным случайным значением. Не заменяйте его на короткий пароль в исходном коде или свойствах: сервер хранит только соль и хеш и рассчитан на сгенерированный пароль с высокой энтропией. Изменить логин можно через свойство `ADMIN_USERNAME`, затем сбросить пароль.

Токен GitHub истекает независимо от пароля. При необходимости замените `GITHUB_TOKEN` в свойствах скрипта. Для обновления самого кода Apps Script создайте новую версию через **Управление развертываниями → Изменить → Новая версия**. Сохраните прежний URL развертывания.

## Что защищено

Сессия проверяется на сервере для чтения заявок, смены статусов и публикации. Она действует до часа, может закончиться раньше при очистке кеша Google; после обновления страницы нужно снова войти. Кнопка «Выйти» отзывает текущую сессию. Пароль и сессия не сохраняются в localStorage; GitHub-токен не передаётся в браузер вообще.

Сам HTML админ-панели остаётся публичным статическим файлом, но чтение заявок и изменение сайта без серверной авторизации недоступны. Локальные черновики содержат тексты/проекты, но не заявки и не секреты. Скрытые проекты всё ещё находятся в публичном site.json и истории Git.

У формы есть проверка полей, согласие, поле-ловушка, ограничение частоты и защита от дубликатов при повторе запроса. Значения записываются как текст, чтобы посетитель не мог выполнить формулу Google Sheets. Это базовая защита, а не CAPTCHA: при массовом спаме может потребоваться дополнительный сервис. У Google Apps Script есть квоты; при их исчерпании форма показывает ошибку и не сообщает об успешной записи.

Данные заявок хранятся в вашей приватной Google Таблице. Доступ к проекту Apps Script давайте только доверенным людям: редакторы проекта имеют доступ к его свойствам. Удаляйте ненужные персональные данные из таблицы. Проверьте текст согласия и правила обработки данных для своей деятельности и страны перед приёмом реальных заявок.
