# Портфолио Азамата

Минималистичный адаптивный сайт с админ-панелью, без сборки и серверных зависимостей. Совместим с GitHub Pages, включая размещение в подпапке и собственный домен.

## Разработка

Нужен Node.js 18+. Запуск: `npm start` в корне репозитория. Порт по умолчанию 3000, задаётся через `PORT`. Проверка синтаксиса: `npm run check`.

## Управление

Откройте `admin.html` или ссылку «Управление сайтом» внизу главной страницы.

- Проекты: создание, редактирование, удаление, скрытие и изменение порядка.
- Обложки: JPG/PNG/WebP до 10 МБ; автоматическое уменьшение до 1200 px и преобразование в JPEG. Максимум 450 КБ в представлении data URL на обложку; общий файл публикации — до 900 КБ.
- Тексты: имя, логотип, заголовки, представление, раздел «Обо мне», навыки, доступность, email и Telegram.
- Изменения сохраняются как локальный черновик. Предпросмотр показывает его только в вашем браузере.
- Экспорт и импорт резервных копий; перенос проектов из предыдущей версии возможен на том же адресе и в том же браузере. После смены домена или пути localStorage недоступен: сначала экспортируйте данные на старом адресе.

## Публикация из панели

На GitHub Pages нет серверного входа по паролю. Право публикации проверяет GitHub, а не браузер: панель доступна всем, но изменить общий сайт можно только с разрешением на запись в репозиторий.

1. Создайте fine-grained personal access token: https://github.com/settings/personal-access-tokens/new.
2. Ограничьте доступ только репозиторием сайта; разрешение **Contents: Read and write**. Укажите срок действия.
3. В панели → «Публикация» укажите `владелец/репозиторий`, ветку (обычно `main`) и токен. При переименовании репозитория проверьте это поле. Подключите GitHub.
4. Проверьте предпросмотр и нажмите «Опубликовать изменения». Панель обновит `site.json` одним коммитом. GitHub Pages должен быть настроен на ту же ветку и корень `/`.
5. Дождитесь завершения публикации Pages. Если изменения не видны, проверьте GitHub Actions/Pages и обновите страницу.

Токен хранится только в памяти вкладки, не записывается в localStorage, файл сайта или репозиторий. После перезагрузки подключитесь снова; кнопка «Отключить» удаляет соединение из памяти. Никому не отправляйте токен. При необходимости отзовите его в GitHub. При защищённой ветке с обязательным PR прямое сохранение не сработает — используйте разрешённую ветку публикации или отдельный процесс review.

Панель проверяет SHA перед записью и не перезаписывает более новую версию. При конфликте экспортируйте черновик, загрузите актуальную версию с GitHub и перенесите нужные изменения.

## Данные и ограничения

Публичный сайт читает только опубликованный `site.json`, игнорируя локальный черновик. Скрытые проекты не показываются, но их данные всё равно находятся в публичном JSON и истории Git: не используйте скрытие для конфиденциальной информации. Все файлы и обложки в публичном репозитории открыты посетителям.

Шрифт Manrope загружается из Google Fonts, при недоступности используется системный шрифт. Сервер Node.js нужен только для локальной разработки: на GitHub Pages публикуются статические файлы. Панель изменяет содержимое сайта, но не DNS, настройки GitHub, исходный код или CSS.

## Проверено

В Chromium проверены публичный режим без редактирования, создание и редактирование проектов, скрытие, порядок, черновик после перезагрузки, тексты и контакты, отдельный предпросмотр и мобильная ширина. Через имитацию GitHub API проверены публикация UTF-8, конфликт версий, загрузка актуальной версии, неверный токен и отсутствие токена в локальном хранилище. Реальная публикация содержимого из браузера требует токена владельца и не выполнялась во время разработки.
